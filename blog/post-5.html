Verification Matters More Than Ever

Jul 7, 2026 • Mark Owens

Trust, but verify. It's a well-worn slogan carried on for decades at this point. Setting aside trust for a moment, how do you verify what an AI agent is building in your system? Here are a few things that have helped me in my AI workflow.

Start with a PRD

A Product Requirements Document is an excellent place to start building with an AI agent. If you don't have one, have the agent create it. This does at least 2 things. (1) It clearly defines: what needs to be built, why, and what problem does it solve? How will the feature/module be implemented? It forces you to make decisions (or get clarity from a Product Owner if you're not able) so that your intent is clear. It won't eliminate all the ambiguity but it's a good start. (2) This will expose gaps in your understanding of the thing and more importantly, the AI agent's. That's a good thing. After all if you can't clearly define what's needed and why, you clearly don't have enough information.

Have the Agent break the implementation details into phases

The reason for this is obvious. Agents have way less opportunity to drift or spiral with smaller, clearly defined tasks. You can simply prompt it like this: "Read PRD_Feature and implement Phase 0. All other phases are out of scope." Of course you can add any additional context you like. This helps you verify what the agent is building step by step. You can run the project and test if the behavior is expected or not. It also allows you to see what it's generating and if that matches what you'd expect it to build. For example, is it beginning to overengineer something? If so this is a much easier time to tell the agent: "Why are we adding a new table to the DB for this? "X feature" already works this way in my system and it should behave similarly here."

Implement a Test Suite

You can use any kind you like. I use xUnit. Configuring your test files may take some doing but this is also something that an agent can help you set up if you need it. You can make tests pass for one of the phases in your PRD or you can add it to your Claude.md (or whatever you use) and make the agent verify the code works as expected each step of the way. If there are errors the agent can iterate and fix them until all the tests pass. You can even have it generate a report with each pass like 24 Tests PASS, 0 Tests skipped, 0 Tests Failed. This forces the agent to acknowledge what it's done or failed to do and why. You can take this to another level if you want to like using an MCP plugin like Playwright to have the model run the tests in the browser as well and verify there are no console errors and that the feature is working as designed.

Bonus Points: Have the Agent Generate the Documentation

You've worked through the PRD one phase at a time, and by means of your own review and test suite you've watched it carefully each step of the way. You're ready to ship right? Not quite. While this feature is fresh in your mind go ahead and have the agent generate a "Documentation_Feature.md" (or whatever you want to call it). This will serve as a reference for other devs on your team or even future you. It's important to have more than just how the feature works — you probably have a good idea of that anyway. However, in addition to that have the agent document the tradeoffs considered, why certain decisions were made, and even current gaps or future gotchas that could surface based on how the feature integrates into your system. I can't emphasize this enough, review the output carefully. Even at this late stage a misunderstanding by you or the agent could surface about what this feature is supposed to do or not do. It's better to identify that now rather than in prod.

The take away

AI agents are fundamentally non-deterministic. Using the validation steps here can make the process with them more deterministic which is something all engineers demand from the systems they build. It will not eliminate all bugs or frustrations but it will help you have a more predictable and verifiable workflow with AI agents. The more you can verify what the agent is doing, the more you can trust it to do what you want it to do. I've heard some people say "trust the model". Sure, trust but verify.
